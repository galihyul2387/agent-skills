# دليل المرحلة: خط أنابيب CI/CD والنشر الآلي

تركز هذه المرحلة على أتمتة دورة تسليم البرمجيات بالكامل — من دفع الكود، والفحص والتنسيق، والاختبارات الأحادية، وفحص الثغرات، وحتى النشر التلقائي عبر البيئات.

## 1. المبادئ الأساسية لـ CI/CD

*   **الفشل السريع (Fail-Fast):** ترتيب المراحل الأسرع أولاً (الفحص ➔ الاختبار ➔ الفحص الأمني ➔ البناء ➔ النشر).
*   **التخزين المؤقت للتبعيات:** تقليل وقت التنفيذ بتخزين الحزم مؤقتاً.
*   **تدرج البيئات:** التطوير المحلي ➔ التجريبية (Staging) ➔ الإنتاج (Production).

---

## 2. استراتيجيات النشر والتراجع

*   **النشر الأزرق-الأخضر (Blue-Green):** تشغيل بيئتين متوازيتين للتبديل اللحظي بدون توقف.
*   **النشر التدريجي (Canary):** توجيه 5-10% من الزيارات أولاً للتأكد من الاستقرار.
*   **التراجع التلقائي (Auto Rollback):** العودة للإصدار السابق فور فشل فحوصات الصحة.

---

## ⚡ أوامر سريعة
*   `act` — تشغيل واختبار مسارات GitHub Actions محلياً عبر Docker.
*   `gh workflow run ci.yml` — تشغيل مسار العمل يدوياً.

---

## ✅ قائمة التحقق ومعيار الاكتمال (DoD)

*   [ ] خط الأنابيب يعمل تلقائياً عند الدفع لفرعي `main` و `development`.
*   [ ] بوابات الجودة تفرض تغطية اختبارات ≥ 80% وتقييم SonarQube.
*   [ ] فحص أمان الحاويات مدمج في مرحلة البناء.
*   [ ] آلية التراجع التلقائي مجربة وموثوقة.

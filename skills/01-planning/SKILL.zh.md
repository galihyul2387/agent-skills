# 阶段指南: 需求规划与 PRD 编写

本阶段的目标是在进入 UI 设计或代码编写之前，建立清晰、结构化且可衡量的项目基础。

## 战略步骤

### 1. 范围界定 (Scoping)
*   明确首个版本 (MVP - 最小可行产品) 必须包含的核心功能。
*   将次要功能延后至后续里程碑，防止需求蔓延 (*scope creep*)。

### 2. 用户故事、会话策略与 4 语言规划 (i18n & RTL)
*   **PRD 文档语言选择:** 技术 PRD 与用户故事可根据团队/客户需求选用 **印尼语 (Bahasa Indonesia)** 或 **英语 (English)** 编写。
*   **4 语言界面规划 (i18n & RTL):** 前端用户界面原生规划支持 4 种主流语言：**🇮🇩 印尼语 (ID)**、**🇬🇧 英语 (EN)**、**🇨🇳 中文 (ZH - 简体中文)** 和 **🇸🇦 阿拉伯语 (AR - 支持 RTL 从右到左排版)**。所有 UI 标签文本提取至 4 个 JSON 字典 (`id.json`, `en.json`, `zh.json`, `ar.json`)，且**所有代码标识符必须 100% 保持标准英文**。
*   **用户画像与业务场景:** 明确系统用户角色并制定系统交互场景（如认证流程、交易流程）。
*   **会话策略定义:** 明确规定每个账户在同一时间仅允许在 **1 个设备/浏览器** 上处于活动状态，并限制多标签页并发 (*Single Session & Tab Concurrency Control*)。

### 3. 技术栈选择与兼容性
*   确定前端与后端技术（如 Angular 17+/React, .NET 10/Node/Python/Go, 数据库与 API 层）。
*   确定支持的主流现代浏览器（Chrome, Firefox, Safari, Edge）。
*   确保技术选型与 AI 编程助手 (*Cursor, Claude Code, Copilot*) 高度契合。

## 安全设计基准 (Security by Design)

*   **密钥管理:** 规划使用环境变量 (`.env`) 存储 API 密钥与敏感凭证，严禁在源码中硬编码敏感数据。
*   **最小权限:** 在数据库、API 网关及云基础设施访问设计中严格执行最小权限原则。
*   **数据隐私与合规:** 确保数据存储规划符合加密协议标准 (HTTPS/TLS 1.3, 静态加密)。

## ⚡ 常用命令速查
*   `npm init -y` / `dotnet new sln` / `go mod init` — 初始化项目脚手架。
*   `git init -b main` — 初始化 Git 版本控制仓库并设定 `main` 为默认分支。

## 🛠️ 常见故障排查
*   **需求模糊:** 在编写代码前，通过结构化访谈、原型草图或流程图与业务方对齐。
*   **范围蔓延:** 锁定 MVP 范围，将新增需求统一归入后续 Backlog。

## 📐 命名规范
*   **文档文件:** 采用连字符命名法 (如 `prd-v1.0.md`, `system-architecture-design.md`)。
*   **史诗与故事:** 采用标准前缀编号 (如 `EPIC-01: User Authentication`, `US-01: Single Active Login`)。

## ✅ 检查清单与完成定义 (DoD)

*   [ ] 项目范围 (MVP 与后续规划) 明确且各方达成一致。
*   [ ] 文档语言已选定 (**印尼语** 或 **英语**) 并在全文中保持统一一致。
*   [ ] 4 语言界面 (含阿拉伯语 RTL 布局) 已完成前期规划。
*   [ ] 用户故事、验收条件及边缘用例已完整记录。
*   [ ] 单设备单活动会话策略 (1 个设备 & 1 个活动标签) 已明确规划。
*   [ ] 技术栈、浏览器兼容性及 DevSecOps 安全基线已通过评审。

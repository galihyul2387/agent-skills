# دليل المرحلة: التخطيط وإعداد وثيقة المتطلبات (PRD)

الهدف من هذه المرحلة هو إرساء أساس واضح ومنظم وقابل للقياس للمشروع قبل البدء في تصميم الواجهات أو كتابة الكود البرمجي.

## الخطوات الاستراتيجية

### 1. تحديد نطاق المشروع (Scoping)
*   تحديد الميزات الأساسية الإلزامية في الإصدار الأول (المنتج الأدنى القابل للتطبيق - MVP).
*   تأجيل الميزات الثانوية للمراحل القادمة لتجنب تضخم النطاق (*scope creep*).

### 2. قصص المستخدم وسياسة الجلسات والتخطيط لـ 4 لغات (i18n & RTL)
*   **اختيار لغة وثائق PRD:** يمكن صياغة وثائق PRD وقصص المستخدم إما بـ **اللغة الإندونيسية** أو **اللغة الإنجليزية** وفقاً لمتطلبات الفريق.
*   **التخطيط لدعم 4 لغات لواجهة المستخدم (i18n & RTL):** تخطيط الواجهة لدعم 4 لغات رئيسية: **🇮🇩 الإندونيسية (ID)**، **🇬🇧 الإنجليزية (EN)**، **🇨🇳 الصينية (ZH - المبسطة)**، و **🇸🇦 العربية (AR - مع الدعم الكامل لتخطيط RTL من اليمين إلى اليسار)**. فصل نصوص الواجهة في 4 ملفات قواميس JSON (`id.json`, `en.json`, `zh.json`, `ar.json`)، مع **إلزامية بقاء جميع أسماء المتغيرات والبرمجة باللغة الإنجليزية القياسية بنسبة 100%**.
*   **تحديد شخصيات المستخدمين وسيناريوهات العمل:** رسم مسارات التفاعل مع النظام (مثل مسار المصادقة والمعاملات).
*   **تعريف سياسة الجلسة النشطة:** فرض قاعدة السماح بتسجيل الدخول على **جهاز/متصفح واحد فقط** في نفس الوقت، ومنع التبويبات المتزامنة (*Single Session & Tab Concurrency Control*).

### 3. اختيار الحزمة التقنية والتوافق
*   تحديد تقنيات الواجهة الأمامية والخلفية (مثل Angular 17+/React، و .NET 10/Node/Python/Go، وقواعد البيانات وواجهات API).
*   تحديد المتصفحات الحديثة المستهدفة (Chrome, Firefox, Safari, Edge).
*   التأكد من التوافق الفعال مع مساعدي البرمجة بالذكاء الاصطناعي (*Cursor, Claude Code, Copilot*).

## معايير الأمان بالتصميم (Security by Design)

*   **إدارة الأسرار والرموز:** استخدام متغيرات البيئة (`.env`) لحفظ مفاتيح API وبيانات الاعتماد. يُمنع منعاً باتاً تضمين الأسرار في الكود.
*   **أقل الصلاحيات (Least Privilege):** تطبيق مبدأ أقل الصلاحيات عند تصميم الوصول لقواعد البيانات والشبكات.
*   **خصوصية البيانات والتشفير:** ضمان تشفير جميع الاتصالات والبيانات (HTTPS/TLS 1.3).

## ⚡ أوامر سريعة
*   `npm init -y` / `dotnet new sln` / `go mod init` — تهيئة البنية التأسيسية للمشروع.
*   `git init -b main` — تهيئة مستودع التحكم في الإصدارات مع الفرع الافتراضي `main`.

## 🛠️ استكشاف الأخطاء وإصلاحها
*   **غموض المتطلبات:** إيضاح المتطلبات عبر جلسات حوارية ورسوم توضيحية قبل كتابة الكود.
*   **تضخم النطاق:** تثبيت نطاق الـ MVP وترحيل أي طلبات جديدة إلى سجل المهام المؤجلة (Backlog).

## 📐 معايير التسمية
*   **ملفات الوثائق:** استخدام نمط الشرطات (مثل `prd-v1.0.md`, `system-architecture-design.md`).
*   **القصص والملاحم:** استخدام بادئات قياسية (مثل `EPIC-01: User Authentication`, `US-01: Single Active Login`).

## ✅ قائمة التحقق ومعيار الاكتمال (DoD)

*   [ ] تم تحديد نطاق المشروع (MVP والمراحل اللاحقة) والاتفاق عليه.
*   [ ] تم اختيار لغة الوثيقة (**الإندونيسية** أو **الإنجليزية**) والالتزام بها بشكل متسق.
*   [ ] تم التخطيط الاستباقي لدعم 4 لغات للواجهة (مع دعم RTL العربي).
*   [ ] تم توثيق قصص المستخدم ومعايير القبول والحالات الخاصة.
*   [ ] تم التخطيط الصريح لسياسة الجلسة المفردة (جهاز واحد وتبويب نشط واحد).
*   [ ] تم اعتماد الحزمة التقنية وتوافق المتصفحات ومبادئ الأمان DevSecOps.
